Welcome to the official **Trajectory IR** documentation.

Trajectory IR acts as a durable semantic layer for AI agents, wrapping every agent decision and tool execution in a portable, crash-safe format using [DBOS](https://docs.dbos.dev/).

---

## The Problem

Modern AI agents execute complex, multi-step workflows involving external APIs, database writes, and cloud infrastructure changes. When an agent crashes mid-execution (due to network blips, LLM timeouts, or server restarts):

- Unsealed side-effects get re-executed, causing **duplicate charges**, **duplicate emails**, or **corrupted state**.
- The entire agent execution history is lost, requiring expensive re-prompting of LLMs.

---

## The Solution: Block-and-Gate Architecture

Trajectory IR solves agent durability by enforcing a strict 5-phase lifecycle:

1. **Initialization:** Load DBOS execution context and state store.
2. **Decision Formulation:** Formulate tool execution plan.
3. **Decision Sealing:** Seal payload with **RFC 8785 JCS** + **SHA256**.
4. **Effect Classification:** Execute tool based on safety boundary (`PURE`, `READ_ONLY`, `IDEMPOTENT_WRITE`, `NON_IDEMPOTENT_WRITE`).
5. **Observation Appending:** Log SHA256 observation node into `.tir` package.

```python
from trajectory_ir.runtime import Trajectory
from trajectory_ir.effects import EffectClass
from dbos import DBOS

DBOS.launch()

@Trajectory.tool(effect_class=EffectClass.NON_IDEMPOTENT_WRITE)
def deploy_service(name: str):
    return f"Deployed {name}"

@DBOS.workflow()
def run_agent():
    traj = Trajectory.start(tenant_id="prod")
    res = deploy_service("k8s-cluster")
    traj.append_observation(res)
```
